# Архив временно отсутствующих и выведенных устройств

Этот каталог находится вне `packages`, а файлы имеют расширение
`.yaml.disabled`. Поэтому Home Assistant их не загружает.

## Текущий статус

- `air_purifier` — `retired`: очиститель убран из квартиры постоянно.
- `humidifier` — `maintenance`: увлажнитель временно снят и находится в ремонте.

## Возврат увлажнителя

1. Убедиться, что интеграция снова создаёт сущности:
   - `humidifier.xiaomi_p3_946a_humidifier`;
   - `sensor.xiaomi_p3_946a_filter_life_level`.
2. Скопировать архивный файл в активный каталог:

   ```bash
   cp /config/archive/devices/humidifier/room_livingroom_humidifier.yaml.disabled \
      /config/packages/room_livingroom_humidifier.yaml
   ```

3. Вернуть строку статуса, кнопку и callback Telegram по фрагменту
   `archive/devices/telegram_livingroom_restore.md`.
4. Включить `input_boolean.livingroom_humidifier_auto` вручную после проверки.
5. Выполнить:

   ```bash
   ha core check
   ```

6. Только после успешной проверки перезапустить Home Assistant.

## Возврат очистителя

Процедура аналогична, но используется файл из `air_purifier`. Перед возвратом
обязательно проверить фактические entity ID: очиститель помечен как `retired`,
и будущая модель или интеграция может создать другие идентификаторы.

## Важное ограничение увлажнителя

В исходной конфигурации была заявлена блокировка при отсутствии воды, но
подтверждённая сущность датчика воды отсутствовала. Поэтому архивный пакет не
содержит выдуманной проверки. После ремонта её следует добавить только после
проверки реального entity ID или атрибута устройства.
